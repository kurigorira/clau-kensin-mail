## 1. 方針

申込者に日付を自由入力させず、**健診受付が「いま申し込みを受けられる日」をスプレッドシートに入力し、その日だけをフォームのカレンダーで選べるようにする。**

```
[スプレッドシート「受付可能日」]  ← 健診受付8名が編集
        │  GASが10分ごとにJSONを生成・公開
        ▼
   受付可能日JSON（日付と時間帯のみ。個人情報は含まない）
        │
        ├──→ [フォーム] 選べる日だけを濃く表示。それ以外は押せない
        └──→ [サーバ側] 送信時に同じJSONで再検証（改ざん対策）
```

申込者から見た画面はモックHTMLのとおりです。日付を押すと午前・午後が出て、最大3つまで選ぶと、上から第1〜第3希望になります。

---

## 2. スプレッドシート「受付可能日」シート

台帳と同じファイル内に、別シートとして作ります。

| 列 | 項目 | 入力例 | 説明 |
|---|---|---|---|
| A | 日付 | 2026-12-08 | 日付形式。1日1行 |
| B | 午前 | ◯ | `◯` のときだけ午前が選べる。空欄・`×` は不可 |
| C | 午後 | ◯ | 同上 |
| D | 対象コース | （空欄） | 空欄＝全コース。特定コースのみの日は、コース名を記入 |
| E | メモ | 予備日 | 院内用。フォームには出さない |
| F | 最終更新 | 2026-12-01 09:12 | GASが自動記入 |
| G | 更新者 | 山田 | GASが自動記入 |

### 入力ルール

- **◯を入れた日＝「申し込みを受け付ける日」であって、「予約が確定できる日」ではない。** 申込者にもその旨を画面で伝えます。
- 過去の日付の行は、GASが毎朝「過去分」シートへ自動で移します。手で消す必要はありません。
- 1行目（見出し）と F・G 列はシート保護をかけ、誤操作で壊れないようにします。
- 8名が同時に編集できます。誰がいつ変更したかは、スプレッドシートの変更履歴で追えます。

## 3. 公開するJSONの形式

GASの `doGet` で、以下を返します。

```json
{
  "generated_at": "2026-12-01 09:10:00",
  "days": {
    "2026-12-08": ["午前", "午後"],
    "2026-12-09": ["午前"],
    "2026-12-11": ["午後"]
  }
}
```

- `days` のキーは `YYYY-MM-DD`、値は `午前` `午後` の配列
- **◯が付いていない日は、キーごと出力しない**
- 個人情報は一切含みません。匿名アクセス可で公開します
- 更新は10分ごと。`generated_at` で鮮度を確認できます

## 4. フォーム側の要件（業者作業）

| # | 要件 |
|---|---|
| 1 | ページ表示時にJSONを取得し、`days` にある日だけを選択可能にする |
| 2 | 取得に失敗した場合、または `days` が空の場合、**カレンダーを隠し、電話案内を表示する**（モックの「ただいまインターネットでのお申し込みを停止しています」の表示）。空のカレンダーを出さないこと |
| 3 | 前後の月に候補がないときは、月送りボタンを無効にする |
| 4 | 選択できるのは最大3件。上から第1〜第3希望として送信する |
| 5 | 送信時、**サーバ側でも同じJSONを取得し、選ばれた日付と時間帯が実際に受付可能かを再検証する**。不一致の場合はエラーとし、「選択された日は受付が終了しました。お手数ですが選び直してください」と表示する |
| 6 | サーバ側でのJSON取得は5分間キャッシュしてよい（毎回取得しない） |
| 7 | JavaScriptが無効な環境では、カレンダーの代わりに受付可能日のプルダウンを表示する（サーバ側でJSONを読んで生成） |
| 8 | JSONのURLは設定ファイルに切り出し、当院側で変更できるようにする |

要件5が抜けると、ページを開いたまま数時間放置して送信された場合に、すでに受付を止めた日の依頼が入ります。**必ず実装してください。**

## 5. 運用ルール（院内で決めること）

| # | 事項 | 案 |
|---|---|---|
| 1 | 更新の頻度 | 毎日、朝の受付開始時に翌日以降の状況を反映 |
| 2 | 常に確保しておく候補日数 | 2週間先まで、最低10日分 |
| 3 | 更新の担当 | 日替わり当番（台帳の確認当番と同じ人） |
| 4 | 候補が減ったときの通知 | **選択可能日が7日分を下回ったら、GASが受付担当と情シスへメール通知** |
| 5 | 3日以上更新がないときの通知 | 同様にGASが通知 |
| 6 | 年末年始・臨時休診 | 事前にまとめて行を削除しておく |

4番と5番は必ず入れてください。**このカレンダーは、更新が止まった瞬間にフォーム全体が使えなくなります。** 気づく仕組みがないと、申し込みがゼロになった理由が誰にもわかりません。

## 6. リスクと対応

| リスク | 影響度 | 対応 |
|---|---|---|
| 更新が止まり、選べる日がなくなる | 大 | 枯渇・未更新の自動通知（§5-4, 5-5）。枯渇時は電話案内へ切り替わるので、申込者が困ることはない |
| 受付可能日が外部から見える | 中 | JSONは匿名公開のため、空き状況が誰でも見られる。個人情報は含まないが、**院内で許容できるか確認が必要**（未決事項） |
| 「◯の日なら予約できる」と誤解される | 中 | 画面とメールに「申し込みを受け付ける日であり、確定ではない」と明記。カレンダーの表記も「空き」ではなく「申込可」とするか要検討 |
| 8名の編集による取り違え・誤削除 | 中 | 見出し行と自動記入列をシート保護。変更履歴で復元できる |
| 開いたまま放置して送信され、締切後の日が入る | 中 | サーバ側の再検証（§4-5） |
| GASの実行上限・障害 | 小 | 取得失敗時は電話案内に切り替わる。台帳への起票とは別のスクリプトにし、片方が止まっても他方が動くようにする |

## 7. モックでの確認方法

モックHTMLでは、GASの代わりに当日を基準としたサンプルデータを生成しています（`makeSample` 関数）。

- 濃い数字の日＝申込可。押すと午前・午後が出ます
- 3件選ぶと、4件目でメッセージが出ます
- サンプルデータを空にすると（`return { generated_at: fmtNow(), days: {} };` に変更）、受付停止時の表示を確認できます

本番では、この `AVAIL` をJSONの取得結果に差し替えるだけで動きます。
