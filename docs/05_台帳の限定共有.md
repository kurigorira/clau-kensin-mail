# 台帳の限定共有について

受診者の個人情報が入る台帳を、受付担当8名だけが見られる状態にする方法の検討。

---

## 結論

**Googleスプレッドシートの「特定のユーザーに共有」で、8名それぞれのアカウントを個別に追加する。**
これ以外の方法は、いずれも条件が悪いか、この規模には過剰です。

ただし前提として、**Google Workspace（有償・独自ドメイン）を使えるかどうかで、安全性が大きく変わります。**

---

## 1. Webでの「限定公開」の方式比較

| 方式 | 認証 | この用途での評価 |
|---|---|---|
| **A. 特定ユーザーに限定共有**（スプレッドシートを直接共有） | Googleアカウント | **採用。** 8名を個別に追加。誰が見られるか一覧で確認でき、外れた人は即座に切れる |
| B. リンクを知る全員 | なし | **絶対に不可。** URLが1回漏れたら全件が外部から読める。メールやLINEで転送された時点で終わり |
| C. GAS Webアプリで閲覧画面を作る | Googleアカウント | 「アクセスできるユーザー」を*自分のみ*または*同じドメイン内*にすれば安全。ただし**全員に設定すると認証なしで公開される**。作る手間に見合わない |
| D. 病院サイト内にBasic認証をかけたページ | ID/パスワード | **非推奨。** 個人情報を外部レンタルサーバに置くことになる。パスワードの共有・変更管理も発生 |
| E. 院内ネットワークからのみアクセス（IP制限） | ネットワーク | Google側でこれを行うにはWorkspaceの上位プランが必要。この規模には過剰 |
| F. 台帳をGoogleに置かず、院内ファイルサーバのExcel | 院内権限 | Google利用が規程上不可の場合の代替。ただし**8名の同時編集ができず、ファイルロックで運用が止まる** |

---

## 2. Workspace（有償）と無償アカウントの違い

ここが実は最大の分岐点です。

| | 無償のGmailアカウント8個 | Google Workspace（独自ドメイン） |
|---|---|---|
| アカウントの所有者 | **個人。病院ではない** | 病院 |
| 退職・異動時 | **本人がアカウントを持ったまま。共有を外し忘れると見え続ける** | 管理者がアカウントを停止すれば即座に遮断 |
| 2段階認証の強制 | 本人任せ | **管理者が全員に強制できる** |
| 誰がいつ見たかの記録 | 取れない | 監査ログで取れる |
| 担当者不在時のデータ回収 | **不可能に近い** | 管理者がデータを移管できる |
| 費用 | 無料 | 1人あたり月額数百円〜 |

**無償アカウントの寄せ集めは勧めません。** 個人情報を扱う台帳を、病院が管理できないアカウントに共有することになります。監査で必ず問題になりますし、実務上も「辞めた職員のGmailから台帳が見られる」状態を防げません。

8名分で月数千円程度です。**費用対効果としては明確に見合います。**

## 3. 採用案の具体的な設定

### 共有設定

| 設定 | 値 |
|---|---|
| 共有方法 | 特定のユーザーを個別に追加（8名＋情シス1名） |
| リンク共有 | **制限付き（オフ）** |
| 権限 | 受付8名＝編集者／情シス＝オーナー |
| オーナー | **2名にする**（自分1人だと不在時・退職時に誰も管理できない） |
| 編集者による権限変更 | **禁止にする**（共有設定を編集者が変えられないようにする） |
| ダウンロード・印刷・コピー | 必要がなければ無効化 |
| 2段階認証 | 全員必須 |

### シート保護

| 対象 | 設定 |
|---|---|
| 見出し行 | 保護（編集不可） |
| 自動記入列（起票日時・最終更新・更新者） | 保護 |
| 「予約依頼台帳」シート | 運用列（ステータス・担当・確定日時）のみ編集可、申込内容列は保護 |

申込内容列を保護するのは、受付が誤って申込者の入力を書き換えてしまうのを防ぐためです。修正が必要な場合は備考列に記載する運用にします。

### 運用ルール

- 台帳のURLをメール・チャットに貼らない（Googleドライブ上で開く）
- スマートフォンの個人端末で開かない。院内PCのみ
- 職員の異動・退職の都度、共有設定を見直す（**確認日を決めて年2回棚卸し**）
- 月1回、CSVで院内サーバへエクスポートしてバックアップ
- 保持期間は1年。経過分はCSVへ退避して台帳から削除

## 4. 残るリスク

| リスク | 対応 |
|---|---|
| 院内PCの画面を関係者以外に見られる | 台帳を開くPCの設置場所を確認する。スクリーンロックの徹底 |
| 共有を外し忘れる | 年2回の棚卸しを実施日込みで決める |
| 誤って行を削除する | スプレッドシートの版履歴から復元可能。復元手順を1枚にまとめておく |
| オーナー1名体制 | オーナーを2名にする（上記のとおり） |
| Google側の障害 | 台帳が開けなくても受付メールは届く。メールが実質的なバックアップになる |

---

## 5. 確認が必要なこと

| # | 確認内容 | 相手 |
|---|---|---|
| 1 | Googleクラウドに受診者の個人情報を置いてよいか | 個人情報保護担当・徳洲会本部 |
| 2 | Google Workspaceの契約が可能か。既に院内で使っていないか | 事務長・情報システム |
| 3 | 受付担当8名に院内で管理されたアカウントを配れるか | 情報システム |
| 4 | 台帳を開くPCの設置場所（画面が見える範囲に部外者が通らないか） | 健診部門 |

1が「不可」の場合、この文書の前提が崩れます。**着手前に必ず確認してください。**
