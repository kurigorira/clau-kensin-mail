この仕様書は、フォーム送信時に発行する2通のメールの形式を定めるものです。
実際の本文は、モックHTMLで入力・確認すると実データで表示されます。**そちらが正であり、本書はその補足です。**

---

## 0. 最重要事項

**院内受付宛メールの `#DATA_BEGIN` 〜 `#DATA_END` ブロックは、当院側で機械的に読み取り、管理台帳へ自動転記します。**

- キー名、値の形式、JSONの記法を変更しないこと
- ブロックの前後に文字・空行を挿入しないこと
- `#DATA_BEGIN` と `#DATA_END` は行頭から始め、その行に他の文字を含めないこと
- JSONは1行で出力すること（整形・改行を入れない）
- 文字コードは UTF-8

このブロックが崩れると、台帳への転記が全件停止します。本文の見た目（■の記号、全角スペースによる字下げ等）は変更いただいて構いませんが、このブロックだけは厳守してください。

### 本文の構成

```
（1）冒頭2行　… 受付した旨と、折り返し電話の依頼
（2）受付番号・受付日時
（3）■ 連絡先

（6）■ 安全確認　… 該当ありまたはわからない の場合、行末に「★要確認」を付ける
（7）■ ご質問・ご要望
（8）機械可読ブロック
```

### 機械可読ブロック

```
========== 以下はシステム処理用（編集しないでください） ==========
#DATA_BEGIN
{"uketsuke_no":"20261201-0001","uketsuke_at":"2026-12-01 21:14:32", ... }
#DATA_END
```

## 3. 申込者宛メール（自動返信）

| 項目 | 内容 |
|---|---|
| 差出人 | `長崎北徳洲会病院 健診センター <kenshin-form@nk-toku.jp>`（仮） |
| 件名 | `【長崎北徳洲会病院】健診の予約依頼を受け付けました（{受付番号}）` |
| Reply-To | 設定しない（送信専用） |

### 記載する内容

1. **冒頭3行以内に「受付の確認であり、予約は確定していない」旨**
2. 折り返し連絡の目安（2営業日以内、日曜・祝日を除く）
3. 受付番号・受付日時
4. 希望コース、第1〜第3希望日
5. 3営業日を過ぎても連絡がない場合の電話番号
6. 健診センターの連絡先・所在地
7. 送信専用である旨

### 記載してはいけない内容

- **安全確認の回答（妊娠・体内金属・造影剤・服薬）** — 家族共用のメールアドレスに届く場合を想定し、健康状態に関する情報は返信に含めません
- 保険証の記号・番号
- 生年月日
- 備考欄の内容

## 4. 送信処理の要件

| # | 要件 |
|---|---|
| 1 | 入力検証はサーバ側でも必ず行う。クライアント側だけの検証は不可 |
| 2 | ハニーポット項目（`website`）に入力がある場合、メールを送信せず、完了画面のみ表示する |
| 3 | 画面表示から送信までが5秒未満の場合、bot とみなし同様に破棄する |
| 4 | 同一IPからの送信は10分間に3件までとする |
| 5 | 受付番号はサーバ側で採番し、重複しないこと |
| 6 | 院内受付宛メールの送信に失敗した場合、完了画面ではなくエラー画面を表示し、**電話番号を大きく案内する** |
| 7 | 全ページHTTPSで提供する |
| 8 | 入力内容をサーバ上のファイルやデータベースに保存しない（メール送信のみ） |
| 9 | 希望日は、受付可能日データ（別紙「受付可能日カレンダー仕様」）に存在する日付・時間帯であることをサーバ側でも検証する。不一致の場合は送信を受け付けず、選び直しを促す |
| 10 | JavaScriptが無効な環境でも、全項目が表示された状態で入力・送信できること |

## 5. 見積前にご回答いただきたい事項

1. サーバのPHPバージョン
2. メール送信の方式（`mail()` 関数／SMTP）と、送信元に使用できるメールアドレス
3. 当院ドメイン（nk-toku.jp）のSPFレコードの現状。未設定の場合、設定の可否と作業主体
4. コース名などの選択肢を当院側で変更できるようにする方法（設定ファイル方式など）と、その場合の追加費用
5. 当院が公開するJSON（受付可能日）を、フォーム表示時とサーバ側検証時に取得する実装の可否と追加費用
6. JavaScriptが無効な環境での代替表示（受付可能日のプルダウン）の実装可否
