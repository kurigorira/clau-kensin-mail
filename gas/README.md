# gas/ — 予約依頼フォーム（GAS Webアプリ）

申込画面の配信から、台帳への書き込み、メール送信、定期通知までの一式。

**半年後の自分が読むことを前提に書いてある。** 迷ったら `CLAUDE.md` の「判断に迷ったときの基準」に戻ること。

---

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `config.gs` | **変わる値の集約。** コース・オプション・料金・宛先・閾値・台帳の列定義 |
| `main.gs` | `doGet`（画面配信）／`doPost`（送信受付）。完了・エラー・確認の各画面もここ |
| `form.gs` | サーバ側の入力検証、受付可能日の再検証、迷惑送信対策 |
| `sheet.gs` | 台帳への行追加、受付番号の採番、受付可能日の読み込み |
| `mail.gs` | 受付担当への通知、申込者への自動返信、機械可読ブロック |
| `notify.gs` | 枯渇・未更新の通知、過去日の移動、保持期間1年の退避と削除 |
| `index.html` | 申込画面。選択肢は config.gs から受け取る |

`tools/` にあるものは **GAS へは上げない**（`gas/` の外に置いてあるのはそのため）。

| ツール | 用途 |
|---|---|
| `tools/gas-sandbox.js` | GAS の API を差し替えて `.gs` を手元で動かす土台。下の3つが使う |
| `node tools/local-test.js` | `doPost` を手元で通す。68項目 |
| `node tools/render-form.js` | `index.html` を普通の HTML に書き出して見た目を確認する |
| `node tools/render-screens.js` | 全画面（入力・確認・完了・エラー・停止中）を `preview-screens/` に書き出す |
| `node tools/shoot-screens.js` | その画面を撮って `docs/screens/` に入れる |

`shoot-screens.js` だけ **playwright が要る**。プロジェクトの依存にはしないので、
使うときだけ別の場所に入れて `NODE_PATH` で渡す（手順はファイル冒頭のコメント）。

画面サンプル（`docs/kensin-form-screens.html`）は受付担当に文言を見てもらうための資料。
`gas/index.html` や `config.gs` を直したら、`render-screens.js` → `shoot-screens.js` の順で
撮り直し、画像とサンプルの両方をコミットする。

## セットアップ手順

### 1. スプレッドシートを作る

1つのファイルに、次の2枚のシートを作る。シート名は `config.gs` の値と一致させること。

**「予約依頼台帳」** — 見出しは手で作らない。後述の `setupLedgerSheet()` が作る。

**「受付可能日」** — 1行目に見出しを手で入れる。

| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| 日付 | 午前 | 午後 | 対象コース | メモ | 最終更新 | 更新者 |

- B・C に `◯` を入れた日時だけが申込画面に出る。空欄や `×` は不可の意味
- F・G は GAS が自動で書く。**手で触らない**（シート保護をかける）
- 過去日は毎朝、自動で「過去分」シートへ移る。手で消さなくてよい

### 2. スクリプトを用意する

1. スプレッドシートから「拡張機能 → Apps Script」を開く
2. `gas/` の `.gs` と `index.html` を貼る（`index.html` は HTML ファイルとして作る）
3. **`config.gs` の先頭を実物の値に差し替える**
   - `SPREADSHEET_ID` … 台帳のスプレッドシートID（URL の `/d/` と `/edit` の間）
   - `MAIL_TO_STAFF` … 受付担当の宛先
   - `MAIL_TO_SYSADMIN` … 情シスの宛先

`SPREADSHEET_ID` が空のままだと、動かしたときに「未設定です」という例外が出る。黙って別の場所へ書きに行くより、止まったほうが安全なのでそうしてある。

### 3. 初期化を実行する

エディタから、この2つを1度ずつ実行する。

| 関数 | すること |
|---|---|
| `setupLedgerSheet()` | 台帳の見出し行を作り、運用列（A〜F）を固定する。既に行があれば何もしない |
| `setupTriggers()` | 定期実行を登録する（下表） |

さらに、**`onEditAvailability` は手で登録する必要がある。** エディタの「トリガー」から、
イベントソース＝スプレッドシートから、イベントの種類＝編集時、関数＝`onEditAvailability` で追加する。
単純トリガーの `onEdit` では編集者のメールアドレスが取れないため、インストール可能なトリガーにしてある。

### 4. デプロイする

「デプロイ → 新しいデプロイ → ウェブアプリ」

| 設定 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分**（台帳への書き込み権限が要るため） |
| アクセスできるユーザー | **全員**（申込者はログインしないため） |

発行された `/exec` の URL を、業者へのリンク追加依頼（`docs/06`）で使う。

### 5. 疎通確認

`docs/01` 付録E のとおり、ダミー10件で確認する。特に次の3点。

- 受付メールが迷惑メールフォルダに入らないか（**1週間は毎日確認する**）
- 日本語が文字化けしないか
- 同時に送っても受付番号が重複しないか

## 定期実行

`setupTriggers()` が登録するもの。

| 関数 | いつ | すること |
|---|---|---|
| `checkAvailability` | 毎日 8時 | 選択可能日が7日分を下回る、または3日以上更新がなければ通知 |
| `archivePastAvailability` | 毎日 5時 | 受付可能日の過去日を「過去分」シートへ移す |
| `purgeOldApplications` | 毎月1日 3時 | 保持期間（1年）を過ぎた申込をCSVへ退避してから台帳から削除 |

**`checkAvailability` は止めないこと。** 受付可能日の更新が止まるとフォーム全体が使えなくなるが、
気づく仕組みが無いと「申し込みがゼロになった理由が誰にも分からない」状態になる。

**`purgeOldApplications` も止めないこと。** 保持期間1年は 2026-09-16 のクラウド利用承認に
付いた条件で、上限であって目安ではない。放置すると承認条件違反になる。

## 変更しそうな箇所

ほとんどの変更は **`config.gs` だけ**で済む。

| やりたいこと | 直す場所 |
|---|---|
| コース名・料金の改定 | `config.gs` の `COURSE_LIST` |
| オプション検査の追加・削除・料金改定 | `config.gs` の `OPTION_LIST` |
| 受診区分や、区分ごとの追加項目 | `config.gs` の `KUBUN_LIST` |
| 安全確認の項目・表示条件 | `config.gs` の `SAFETY_LIST` |
| 宛先アドレス・電話番号・受付時間 | `config.gs` の `MAIL_*` と `CENTER` |
| 折り返し連絡の目安日数 | `config.gs` の `CALLBACK_BUSINESS_DAYS` |
| 通知の閾値（7日分・3日） | `config.gs` の `AVAIL_MIN_DAYS` / `AVAIL_STALE_DAYS` |
| 年末年始などに受付を止める | `config.gs` の `IS_SUSPENDED` を `true` にする |

**台帳の列を増やすときは注意。** `config.gs` の `LEDGER_COLUMNS` と `sheet.gs` の
`appendApplication_()` の両方を直す必要がある。片方だけだと「列数が定義と一致しません」
という例外で止まる（気づかず列がずれるより、止まるほうが安全なのでそうしてある）。

変更したら `node tools/local-test.js` を通してから反映すること。

## バックアップと復旧

### バックアップ

| 対象 | 方法 | 頻度 |
|---|---|---|
| 台帳 | スプレッドシートを「ファイル → ダウンロード → CSV」で院内サーバへ | 月1回 |
| 受付メール | 受付用メールボックスにそのまま保持 | 1年 |
| スクリプト | このリポジトリ（`gas/`）が原本 | 変更のたびにコミット |

### 復旧手順

**ここは実際に1度試しておくこと。** バックアップを取っていても戻せないケースが非常に多い。

**台帳を誤って壊した・行を消した場合**

1. スプレッドシートの「ファイル → 変更履歴 → 変更履歴を表示」から、壊す前の版に戻す
2. 戻せない場合は、月次のCSVから復元する
3. CSV以降の申込は、**受付メールから復旧できる**。受付担当宛メールの
   `#DATA_BEGIN` 〜 `#DATA_END` に、申込内容が JSON で入っている。
   これを台帳の列順に並べ替えて貼る

案D では台帳へ直接書き込むので、この機械可読ブロックを解析して起票することはない。
それでも残してあるのは、**この復旧経路のため**（と、案Bへ切り戻す場合の発注仕様のため）。

**スクリプトを壊した場合**

このリポジトリの `gas/` から貼り直す。`config.gs` の `SPREADSHEET_ID` と
メールアドレスの差し替えを忘れないこと。

**スプレッドシートごと消した場合**

新しく作り直し、`setupLedgerSheet()` と `setupTriggers()` を実行して
`SPREADSHEET_ID` を差し替える。データは月次CSVと受付メールから戻す。

## よくあるトラブル

| 症状 | 原因と対処 |
|---|---|
| 画面が「停止しています」になる | 受付可能日に◯が1つも無い。シートに翌日以降の◯を入れる |
| ◯を入れたのに画面に出ない | 過去日になっていないか。または日付列が文字列になっていないか（日付形式で入れる） |
| 「送信できませんでした」が出る | 台帳へ書けていない。`SPREADSHEET_ID` とシート名を確認。実行ログに原因が出ている |
| 受付メールが届かない | 迷惑メールフォルダを確認。SPF の設定も確認する。**台帳には入っているので申込自体は残っている** |
| 受付番号が飛ぶ | 仕様。エラーで途中終了した分は採番されないことがある。重複しなければ問題ない |
| 「列数が定義と一致しません」 | `LEDGER_COLUMNS` と `appendApplication_()` の片方だけを直している |
| 通知メールが来すぎる | `AVAIL_MIN_DAYS` / `AVAIL_STALE_DAYS` を調整する。**止めるのではなく閾値を変える** |

## 実装していないこと（できないこと）

**接続元IPの取得。** GAS の `doPost` では取れない。そのため次の2つは案Dでは実装できない。

- `docs/01` 付録B の AF列「送信元IP」→ 列を廃止した
- `docs/01` §9 の「同一IPからの短時間の連続送信を制限」

迷惑送信対策は `docs/01` F-08 のもう一方、**ハニーポット＋送信間隔チェック**で対応している
（`config.gs` の `HONEYPOT_FIELD` / `MIN_SUBMIT_SECONDS`）。それでも増える場合は
reCAPTCHA の追加を検討する。

**そのほか、意図的に作っていないもの**は `CLAUDE.md` の「やらないこと」を参照。
